# 시차 알파 콘솔 (tzalpha)

미국 종가와 국내 시가 사이 4시간의 시차를 이용한 매매 가설을,
**여러 개 만들어 두고 시간을 들여 걸러내는** 도구입니다.

---

## 1. 설치

```bash
pip install yfinance pandas numpy
```

## 2. 첫 실행

```bash
python run_daily.py     # 수집 → 평가 → 예측 기록 → viewer.html 생성
python serve.py         # 브라우저가 자동으로 열립니다
```

`serve.py`를 띄우면 화면의 **[데이터 갱신]** 버튼이 실제로 동작합니다.
`viewer.html`을 그냥 더블클릭해서 열면 화면은 보이지만 갱신 버튼은 안 됩니다.
(브라우저 혼자서는 파이썬을 실행할 수 없기 때문입니다.)

인터넷 없이 화면만 먼저 보고 싶으면:

```bash
python src/seed_demo.py    # 가짜 데이터 생성
python src/report.py       # 뷰어만 생성
```

> `seed_demo.py`가 만든 숫자는 전부 난수입니다. 판단 근거로 쓰지 마세요.

## 3. 매일 자동 실행 (윈도우)

작업 스케줄러 → 기본 작업 만들기 → 매일 07:00 →
프로그램: `python`, 인수: `run_daily.py`, 시작 위치: 이 폴더 경로.

07:00인 이유: 미국장 마감(05:00) 이후, 국장 개장(09:00) 이전이라
**결과를 모르는 상태에서 예측이 기록**되기 때문입니다.

## 4. 파일 구조

```
config.json           수집할 종목 목록. 티커 추가는 여기.
models.json           모델 등록부. 모델 추가는 여기.  ← 대화하며 계속 늘릴 파일
events.json           지정학/전쟁/실적 등 '왜'를 손으로 적는 메모장
run_daily.py          매일 실행할 진입점
serve.py              로컬 서버. 갱신 버튼을 동작시키는 부분
viewer_template.html  뷰어 원본 (__BUNDLE__ 자리에 데이터가 주입됨)
viewer.html           생성된 결과물. 이 파일 하나만 있으면 어디서든 열림
src/
  sources.py          데이터 소스 어댑터. 한투 API로 갈아끼울 때 여기만 수정
  collect.py          가격 수집 → data/prices.csv 누적
  engine.py           날짜 정렬 + 신호 계산 + 예측 사전기록
  report.py           뷰어 생성
  seed_demo.py        데모 데이터 (테스트용)
data/
  prices.csv          누적 가격 (지우지 말 것)
  predictions.csv     예측 장부 (append-only. 절대 손으로 고치지 말 것)
```

## 5. 이벤트 메모 (`events.json`)

데이터만으로는 "왜 그렇게 움직였는지"를 알 수 없습니다.
신호가 유난히 크게 나온 날만 한 줄씩 적어두세요. 매일 안 적어도 됩니다.

```json
{
  "from": "2026-08-12", "to": "2026-08-12",
  "tag": "geopolitics",
  "keys": ["MU", "SNDK"],
  "title": "대중 반도체 수출 규제 확대 발표",
  "memo": "메모리 3사 전부 급락. 섹터 전체 이슈로 판단."
}
```

이게 쌓이면 나중에 **"지정학 이슈 국면에서만 잘 듣는 모델"** 같은 걸 골라낼 수 있습니다.
적어둔 메모는 해당 날짜 신호 카드에 자동으로 붙습니다.

## 6. 모델 추가하는 법

`models.json`의 `models` 배열에 한 덩어리 추가하면 끝입니다. 코드는 안 건드립니다.

```json
{
  "id": "M009",
  "name": "엔비디아 급등 → 한미반도체 추종",
  "hypothesis": "NVDA가 3% 이상 오른 다음날 HBM 밸류체인이 따라간다",
  "created_at": "2026-08-05",
  "status": "live",
  "executable": true,
  "signal": { "key": "NVDA", "field": "ret_close" },
  "rule": { "long_above": 0.03, "short_below": -0.03 },
  "trade": { "key": "HANMI", "entry": "open", "exit": "close", "direction": "follow" },
  "note": "왜 이 가설을 세웠는지 여기 적어둘 것"
}
```

`created_at`은 **오늘 날짜로 적고, 나중에 절대 고치지 마세요.**
이 날짜 이후 성적만이 진짜 증거입니다.

---

## 7. 이 도구를 쓰는 규칙

읽고 넘기지 말고, 어길 때마다 손실이 난다고 생각하세요.

1. **백테스트 성적으로 모델을 채택하지 않는다.**
   과거 재현은 아이디어를 버리는 데만 씁니다. 채택은 사전기록으로만.

2. **사전기록 30건 미만이면 판단하지 않는다.**
   30건은 최소선이지 충분선이 아닙니다. 60건 이상을 권장합니다.

3. **동전던지기(M008)를 못 이기는 모델은 즉시 폐기한다.**
   비용을 뺀 뒤의 진짜 기준선입니다. 50%가 아닙니다.

4. **노이즈 기준선을 못 넘으면 아무것도 발견하지 못한 것이다.**
   모델을 많이 만들수록 기준선이 올라갑니다. 순위표 상단 배너에 항상 표시됩니다.

5. **모델을 지우지 않는다.** 실패한 모델을 지우면 "몇 개를 시도했는지"를 잊어버리고,
   그러면 노이즈 기준선이 거짓말이 됩니다. `status`를 `retired`로 바꾸세요.

6. **모의매매를 3개월 통과하기 전에는 실계좌를 붙이지 않는다.**

## 9. 깃허브 자동화 (PC를 안 켜도 매일 쌓임)

내 PC 대신 **깃허브 서버가 매일 06:30(KST)에 수집**하고, 결과 HTML을 웹주소로 서비스합니다.
형준님은 주소만 열면 됩니다. 폰에서도 봅니다.

### 왜 이게 중요한가

이 프로젝트는 **매일 빠짐없이 쌓이는 것**이 전부입니다.
PC가 꺼져 있던 날은 사전기록이 비고, 표본에 구멍이 납니다.

그리고 덤이 하나 있습니다 — 예측 장부가 깃 커밋 이력에 **타임스탬프와 함께** 박힙니다.
"결과 나오기 전에 기록했다"는 걸 스스로 믿을 필요 없이, 커밋 시각이 증거가 됩니다.
나중에 파일을 손대도 히스토리에 다 남습니다.

### 올리는 순서

1. 깃허브에서 새 저장소를 만듭니다. (예: `tzalpha`)

2. 이 폴더에서:
   ```bash
   git init
   git add .
   git commit -m "최초 커밋"
   git branch -M main
   git remote add origin https://github.com/<내아이디>/tzalpha.git
   git push -u origin main
   ```

3. `config.json`의 `github_repo`를 채웁니다.
   ```json
   "github_repo": "muse2002/tzalpha"
   ```
   화면의 갱신 버튼이 Actions 수동 실행 페이지로 연결됩니다.

4. 저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 바꿉니다.

5. **Actions** 탭 → `매일 수집` → **Run workflow** 를 한 번 눌러 손으로 돌려봅니다.
   성공하면 `https://<내아이디>.github.io/tzalpha/` 에 화면이 뜹니다.

이후로는 아무것도 안 해도 매일 알아서 돕니다.

### 미리 알아둘 것

- **저장소는 공개(public)로 두어야 Pages가 무료입니다.**
  즉 모델과 데이터가 전부 공개됩니다. 감추고 싶으면 비공개 저장소로 두고
  Actions만 쓰면서 `viewer.html`을 직접 내려받아 보면 됩니다. (Pages는 유료 플랜 필요)

- **야후가 클라우드 IP를 가끔 막습니다.** 깃허브 서버 IP는 공용이라
  내 PC보다 차단될 확률이 조금 높습니다. 실패하면 자동으로 이슈(Issue)가 등록되니
  알림으로 바로 압니다. 대개 다음날 정상화됩니다.

- **cron 시각은 정확하지 않습니다.** 깃허브가 혼잡하면 5~30분 밀립니다.
  09:00 개장 전까지 여유를 두려고 06:30으로 잡아뒀습니다.

- **매일 커밋이 쌓입니다.** `prices.csv`가 커지면 저장소도 커집니다.
  몇 년은 문제없지만, 나중에 무거워지면 압축 저장으로 바꾸면 됩니다.

- **로컬 실행도 그대로 됩니다.** `python serve.py` 는 계속 쓸 수 있습니다.
